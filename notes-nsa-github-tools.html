Reverse-engineer binaries safely with Ghidra

  • Use Ghidra instead of paying for IDA Pro. The speaker notes IDA Pro's expert plan lists at €4,999/year while the agency's Ghidra is free with 94,000+ GitHub stars. [11:40] [11:52]
  • Install it on Kali with one apt command — Kali packages Ghidra itself, with the code browser and decompiler included. [12:21]
  • Script analyzeHeadless for batch work. Point it at a folder of samples and run overnight with no window; anything scripted in the GUI works headless, so one script scales to 1,000 files. [12:35]–[12:54]
  • Only open files you wrote yourself or crackme practice files, and only inside a VM — never an email attachment on your main computer. [12:56]–[13:04]
  • Assume any secret baked into a binary is readable in seconds. His demo: a name-scrubbed binary was decompiled in ~8 seconds and the string-compared password ("ETS 7731 NSA" per the captions) recovered — keep keys on the server. [13:14]–[14:06]
  • Know the history of its debug mode: Rob Joyce said on stage there was no backdoor; within hours Matthew Hickey showed Ghidra's debug mode opened port 18001 to the local network, letting anyone who could reach it run code. Debug mode is off by default and 9.0.1 closed the port. [13:39]–[13:57]

Hunt web shells with Yara — and a clean-copy compare

  • Get the NSA/Australian Signals Directorate "Mitigating Web Shells" repo, which ships Yara rules (a core set and an extended set) for finding shells dropped on a server. [4:20] [4:31] [4:37]
  • Run both rule sets — don't trust one. His test: a 3-line shell planted in an uploads folder as avatar.php was missed by the core set and flagged twice (obfuscated functionality, possible indicator) only by the extended set. [4:48]–[5:02]
  • Vet core hits first and expect false positives from extended rules — they flagged a harmless git sample hook script; the README says to vet core hits first and use the compiled rule files (some security software flags the uncompiled ones as malicious). [5:29] [5:45]–[5:53]
  • Keep a known-good copy of your site and diff it against live. One diff printed only the file he planted. Store the clean copy where the server can't write to it and run the compare after every deploy. [5:06]–[5:15] [6:12]
  • Put scanning and comparing on a schedule and read every hit the morning after — a scanner guesses from patterns; a compare tells you what actually changed. Read the file yourself before panicking. [5:57]–[6:11]

Check SELinux enforcement on every Linux box you run

  • Run getenforce on Linux servers you own; the answer you want is enforcing. permissive means SELinux logs what it would have blocked but blocks nothing; disabled means no policy protects the machine at all — the speaker calls permissive/disabled "the first setting to fix." [6:18] [7:21]–[7:44]
  • On Kali, install the selinux-utils package first — getenforce isn't shipped by default. [7:11]–[7:21]
  • Know why it matters: even root only gets exactly what its policy allows, so a hacked service can't step outside its lane. NSA released it under an open-source license in Dec 2000, it merged into the mainline kernel in Aug 2003, arrived on Android in 4.3, and has run every app in enforcing mode since Android 5. [6:30] [6:40]–[6:54]
  • Watch the failure mode: SELinux only blocks what policy forbids, and when it gets in the way people often turn it off. [6:59]–[7:06]

Generate passwords, passphrases, and keys with Rand Pass Generator

  • Use the NSA's Rand Pass Generator for the one passphrase that guards your password manager, and let the manager handle everything else. It draws from a hash-DRBG generator built to a NIST standard and refuses to run if its own self-tests fail. [2:48]–[3:05] [4:15]
  • Build it from source with Java + Ant (one apt install, then ant jar), and run the jar from the folder you built it in — running from your home folder fails with "cannot access the jar." [3:30]–[3:55]
  • Learn the flags: -pw passwords, -pp passphrases, -k keys, -str bits of strength. His test: 96 bits produced three random 16-character passwords; 128 bits produced two 8-word passphrases. [3:57] [3:21]
  • Don't expect a password manager replacement — it's a Java command-line tool with no app and no sync. [3:23]–[3:28]
  • Context for skepticism: this is the agency Reuters says paid RSA $10 million to make a suspect RNG the default (RSA denied any deal; NIST told everyone to stop using that generator in 2014) — but this tool uses a different, still-recommended generator from the same NIST family. [2:32]–[2:47]

Run Apache NiFi only with its defaults locked on

  • Never expose the NiFi canvas — an exposed instance lets whoever reaches it build data flows on your machine. Recent versions start with login and an encrypted connection switched on; leave them that way. [8:39]–[8:48] [9:34]
  • Verify the download before unzipping: Apache publishes a SHA-512 checksum next to the zip — check it first (the video's download was ~850 MB; exact version not repeated to avoid miscaptioning). [8:52]–[9:04]
  • Start it with nifi.sh from the bin folder after exporting JAVA_HOME, expect ~2.5 minutes to an HTTP 200 on its web interface, and stop it with the same script so nothing keeps running in the background. [9:05]–[9:32]

Don't build new crypto on Simon and Speck

  • For your own projects use AES or ChaCha20 from an audited library — leave Simon and Speck to the tiny chips they were made for. [11:31]
  • Understand why they're controversial: experts in Germany, Japan, and Israel fought them because they feared the NSA knew how to break them; a Linux kernel developer wrote a patch to remove them; ISO accepted them only for RFID tags. The NSA answered that 70+ security analysis papers back its conclusion, and the speaker stresses a passing test vector proves the cipher works as published but can't settle the trust question. [9:40]–[10:12] [10:29]
  • Read the spec yourself in under a minute: clone the Simon/Speck Supercop repo, open the reference stream file in the spec 128 folder — the encrypt function is ~10 lines in a 32-round loop; the repo also includes Simon 2 and the Jambu authenticated-encryption scheme. [10:35]–[11:29]

Treat the Enigma Simulator as a history lesson, not a tool

  • Don't protect anything modern with anything like Enigma — it's been broken for nearly a century. [2:26]–[2:31]
  • Use the repo to learn the cryptanalysis that beat it: feed its output back from the same rotor position to see the reciprocal property (and that a real Enigma never encrypts a letter as itself — the habit codebreakers used to discard wrong guesses by the thousand). The bundled notebook walks through breaking it the way Marian Rejewski did in the 1930s. [1:35]–[2:09]
  • Try it on any Kali box: git and Python 3 are already installed — one git clone and step into the folder. [2:14]–[2:25]
